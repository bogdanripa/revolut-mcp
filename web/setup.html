Setup

Connecting takes about a minute. You do it once per business, in your browser — after that your assistant just works, and tokens refresh themselves.

Before you start

You need a Revolut Business account (this is the business API — personal Revolut accounts are not supported) and enough access on it to reach Settings → APIs. That is normally an Owner or Admin.

The account also has to be fully verified. If Settings → APIs shows a Verify identity card where the certificate form should be, Revolut has not finished verifying the business and no API credentials exist yet. Nothing here can proceed until it is done.

That card explains the block but is not where you clear it — verification lives in Revolut's own onboarding, on the Business home screen or in the Revolut Business mobile app, and Revolut emails you when it needs something. The KYB checks ask for a national ID and video selfie for you, the certificate of incorporation or business registration, a description of what the business does, and ID for each director and shareholder above 25%. Revolut aims to review within about a day, though complex applications take longer — see their list of required documents. A sandbox account skips all of it and takes minutes, if you just want to see the flow work.

Anything else that speaks MCP

Add it as a remote / streamable-HTTP MCP server at the same URL. The server advertises OAuth through /.well-known/oauth-authorization-server and supports dynamic client registration, so no client-side credentials are needed.

2. Register the certificate with Revolut

Your assistant will send you to our connect page. It shows you two values; both go into one Revolut form.

  1. Open Revolut → Settings → APIs.

    The connect page has a button that takes you straight to Settings → APIs on the Business API tab, for production or sandbox. If it doesn't land on the API page, navigate by hand: from the Revolut Business home, click your profile icon, then Settings, then APIs. Then click Add API certificate.

  2. Paste the X509 public key.

    Copy it from the connect page — it is this deployment's public certificate. It is public by design; the matching private key never leaves the server. You can also fetch it directly at …/certificate.pem.

  3. Paste the OAuth redirect URI.

    It must match exactly, including the path: …/revolut/callback. A mismatch here is the single most common reason a connection fails.

  4. Choose the permissions to grant.

    Revolut asks what the integration may do. Read your account details is required — without it nothing works. Add the payment permissions only if you want your assistant to be able to move money.

  5. Save, then copy the Client ID.

    Revolut shows a Client ID next to the new certificate. Paste it into the connect page and press Continue.

3. Approve on Revolut

You land on Revolut's own consent screen. Approve, and the browser comes back here and hands your assistant a token. If Revolut inserts an identity re-verification step that ends with "Successfully authorized — please return to your original tab", switch back to the tab you started in; that is where the redirect completes.

We verify the connection by reading your account list before telling your assistant it is connected, so a consent granted with no permissions is caught immediately rather than surfacing later as a confusing tool error.

Keeping it working

Revolut access tokens last about 40 minutes and are refreshed automatically. The underlying consent lasts roughly 90 days, and the certificate you registered has its own expiry. When either lapses, reconnect from your assistant — the same Client ID works, so you only redo the approval, not the certificate.

When something goes wrong

What you seeWhat it usually means
"Revolut refused to complete the connection" The redirect URI on the certificate is not an exact match, the certificate is not the one on the connect page, or the approval took more than a couple of minutes.
"Revolut would not let us read your accounts" The consent was granted without Read your account details. Reconnect and tick it.
A tool fails with HTTP 403 That specific permission was not granted. get_connection_status shows what was.
"Bad Request — check the redirect URL" Revolut rejects localhost redirect URIs. Use the URI shown on the connect page.
Everything worked, then stopped after months The 90-day consent window expired. Reconnect from your assistant.

Running it yourself instead

The same server runs over stdio for a single business, with no server and no database. You generate your own keypair and register it exactly as above, using your own redirect URI.

openssl genrsa -out privatekey.pem 2048
openssl req -new -x509 -key privatekey.pem -out publickey.cer -days 1825 -subj "/CN=revolut-mcp"

Then point an MCP client at it:

claude mcp add revolut \
  --env REVOLUT_CLIENT_ID=your_client_id \
  --env REVOLUT_PRIVATE_KEY_PATH=/absolute/path/to/privatekey.pem \
  --env REVOLUT_REDIRECT_URI=https://example.com/ \
  --env REVOLUT_ENVIRONMENT=production \
  -- node /absolute/path/to/revolut-mcp/dist/index.js

In stdio mode the setup_auth and complete_auth tools walk you through the authorization: the first returns a URL to open, the second takes the code from the redirect. Tokens are written to ./.tokens.json.
